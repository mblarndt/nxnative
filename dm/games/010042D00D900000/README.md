# LEGO® Star Wars™: The Skywalker Saga (`010042D00D900000`)

Update 1.0.8 (`v524288`) over the base game (no other update exists for this title ID), SDK 12.3.6 (NVN API 53), TT Games' NuCore engine on NVN. Modules `main` (the game, 98.5 MB of text, 16 MB of bss), `sdk`, `subsdk0` (GLSLC, not loaded: `main` imports nothing from it) and `subsdk1` (NintendoSDK_movie). The RomFS is 7 TT Games archives (`GAME.DAT`, `GAME0.DAT` … `GAME4.DAT`, `PATCH.DAT`: 15.6 GB, no `.HDR`) and `BootScreen.png`; the DLC (11 add-on contents) are small `.DAT` files of their own. 30 fps by the game's own choice (present interval 2).

Work in progress: the Mac host runs it from the language menu through the intro film, the title screen and the new-game menu into the first level (Tantive IV, Leia and the rebel troopers in colour), with the menus' text, icons and the 3D scenes drawn; what is left is listed under Open.

## What it needs

| Setting | Where | Why |
|---|---|---|
| `mem_reserve 0x100000000`, `mem_alias 0x10000000`, `mem_stack 0x10000000`, `app_pool 0xCD500000`, `mem_used 0xcdbc000` | [`game.tsv`](game.tsv) | the provisional profile's values, kept: the NPDM declares no system resource, the game sets a heap with `SetMemoryHeapSize` (asks for 5.95 GB and takes 2 MB less until the pool allows it, see [`SetHeapSize` above the heap region](../../../docs/reference/memory.md#a-heap-request-beyond-the-heap-region-returns-resultoutofmemory)): 2.99 GB |
| `tex_flush_upload on`, `tex_dirty_upload on`, `tex_init_upload on`, `tex_copy_mirror on` | `game.tsv` | the game reads texture files into one 1.4 GB pool and makes textures over them, writes some by CPU, fills the others by `CopyBufferToTexture`, and its memory manager moves textures about in the pool with `CopyBufferToBuffer` ([NVN objects](../../../docs/reference/nvn-objects.md#a-textures-content-only-went-in-through-a-gpu-copy-and-the-game-moves-its-textures-about-in-the-pool-tex_copy_mirror)) |
| `romfs_marker GAME0.DAT`, `zip_store .dat:.png:.metallib` | `game.tsv` | |

No `patches.py`, no `sdk_patches.py` cut, no `pad_layout`.

## Shaders

98,023 programs in 19,755 different code areas, all offline: 664 in `main` (code area right before the control section, no pointer to it) and 97,359 in the `*.nnx_shaders` files inside the DAT archives (48,472 vertex, 48,818 pixel, 733 compute). Neither is a container the split knew; see [Control sections with their code area right before them](../../../docs/reference/shaders.md#control-sections-with-their-code-area-right-before-them-in-main-and-in-tt-games-dat-archives) and [TT Games DAT archives](../../../docs/reference/shaders.md#tt-games-dat-archives). The first build decodes 42 GB of archives (36 s) and translates and compiles every shader (about 1 min and more than an hour); later builds hit the caches. No shader pairs: every vertex shader is paired with the single-stage cover.

## Found on this game

- **Boot:** `SetHeapSize` above the heap region ([memory](../../../docs/reference/memory.md#a-heap-request-beyond-the-heap-region-returns-resultoutofmemory)); the notification pop that never gave the core back ([threads](../../../docs/reference/threads.md#native-hle-waits-release-the-guest-core)); the audio renderer's event on a stack ([audio](../../../docs/reference/audio.md#the-games-renderer-event-is-a-local-of-the-function-that-opens-it)).
- **Black picture at 30 fps:** the dynamic constant buffer objects hold the game's own offset and size in the `NVNbuffer` ([NVN objects](../../../docs/reference/nvn-objects.md#a-game-writes-the-offset-and-size-into-its-nvnbuffer-buf_t)).
- **Red lines:** `nvnCommandBufferSetStencilCullCriteria` is a hint.
- **No text, no icons, empty or shifted textures:** a texture only the GPU copy filled came out of every move as zeros ([`tex_copy_mirror`](../../../docs/reference/nvn-objects.md#a-textures-content-only-went-in-through-a-gpu-copy-and-the-game-moves-its-textures-about-in-the-pool-tex_copy_mirror)), a texture made over data the game had read into the pool was never uploaded (`tex_init_upload`).
- **Abort in the first 3D scene:** the luminance histogram's image atomics, one image declared as integers, atomically and as floats ([shaders](../../../docs/reference/shaders.md#an-image-the-shader-reads-as-integers-atomically-and-as-floats-imga-with-two-img-views)).
- **Crash in `keys_hash`:** a stage entry the game left unset (control pointer 1) was read as a control section.
- **Black 3D picture (fixed):** the bloom target (RG11B10F) was all NaN, because a pass that loads a float target and overwrites it with ONE / ZERO blending kept the NaN of its old content; the tonemap pass turned it into black (intro film after its first seconds, the main menu's background, every level). The pipeline no longer blends ONE / ZERO ([rendering](../../../docs/reference/rendering.md#one--zero-blending-is-not-blended)).
- **Blocks in the glow around lightsabers (fixed, seen in 4 of 4 dumps before, in none of 11 after):** hard-edged patches of about 16×8 pixels in the soft halo, already in the HDR scene target before the bloom, in some frames and not in others. The glow, soft-particle and light-volume draws sample the depth buffer they test against (GPU-driven indirect draws, one pass each), which is undefined in Metal. `feedback_snap depth` makes them read a snapshot of the depth ([rendering](../../../docs/reference/rendering.md#depth-attachment-sampled-by-its-own-pass)); it costs about 0.8 ms of GPU time in a frame with sabers (40 more encoders). Frames of the intro with a lightsaber that were checked: Vader and Luke on the stairs, the Geonosis arena, the duel in front of the light columns. A frame-exact before / after could not be made (the film's timing differs from run to run).
- **Hitches at the cuts of the intro (mostly fixed):** single frames of 25–60 ms with almost nothing drawn came from the game filling its 3D textures (a 192×40×264 volume) one slice at a time through the buffer → texture copies `tex_copy_mirror` turns into texel writes; each write decoded and encoded the whole volume ([reference](../../../docs/reference/nvn-objects.md#a-3d-texture-written-slice-by-slice-decoded-and-encoded-the-whole-volume-for-every-slice)). Left: the first frame of a new scene with 100–160 first texture uploads (20–80 MB) takes 10–25 ms of submit (translating draws it has never seen, creating the textures), and a few heavy scenes (the Geonosis arena, the duel in front of the light columns) run at 15–17 ms of GPU time, about the frame budget.

## Frame rate

`fps_target 60` (the app's **Bildrate** setting offers 30 and 60): the host writes NuCore's video swap mode (1 at 60, 3 at 30) and its retrace rate into the game each frame and presents every vsync at 60 ([reference](../../../docs/reference/frame-rate.md#tt-games-video-swap-mode-60-fps-in-two-variables)). On an M-series Mac the first level holds 60 fps (frame time p50 16.67 ms, p95 16.9 ms); the intro film and the walking speed match 30 fps. The game was built for 30: its animations and effects may be authored for that rate (not looked at beyond the intro film and the first minutes of the level).

## Pipelines on a first start

`pso_manifest.tsv` is the prewarm seed list recorded over the bring-up runs (boot, logos, the intro film, the title, a save load and the first level): 3,780 shaders, 1,511 render pipelines, 38 compute pipelines. Without it a first start compiled the intro film's scenes' pipelines as they came (up to 91 pipelines and 104 shader libraries in one frame: 50–90 ms hitches, the stutter of the film at 60 fps); with it they are built before the first frame (3.8 s on 10 workers on top of the one-off pipeline prebuild), and the film's frames with new pipelines went from about a dozen to one in a cold run. Hitches that remain in the film are texture upload bursts (70–80 MB in one frame at a scene cut) and some frames whose submit side takes 40–60 ms with nothing new in them.

## Open

- **Runs that stop for good (not reproduced since):** two kinds were seen, at boot (the first loading screen, texture uploads stuck from the first frame, the audio renderer silent) and while a level loads (the loading screen with its hints animates, the workers idle, the render and main thread keep running, a few NVN calls a frame). Both came in test runs while a forgotten second host (5 cores busy, the same save and pipeline-archive folders) was alive; after it was killed, 7 runs to the first level (alone, with 5 busy loops, beside a second host in the same folder) and about 45 boots (3 hosts at once in folders of their own) ran through. What both stopped runs share: another host was using the same save folder and was killed or running while they started (a half-written save is a possible cause, not checked). The thread dump (`DM_CTL threads`) showed no host thread stuck. A cause is not known; if it comes back, take `threads` twice (it prints a guest backtrace for threads asleep in a poll loop) and keep the run alive.
- **Shader tables:** 98,025 shaders (650 from `main`, the rest from the DAT archives and the captured programs); the 32 captured programs live in [`shader_capture`](shader_capture) (the split reads the folder itself; the last two, the movie plugin's YUV blit, made the Lucasfilm Games logo film draw: [reference](../../../docs/reference/shaders.md#programs-the-host-captured-kept-in-the-profile-shader_capture)). The movie plugin's other programs, if any, would show as `not in the shader map`: none do so far.
- **A second audio renderer** (48 kHz, 32 voices, opened about 50 s into the boot) is driven now ([reference](../../../docs/reference/audio.md#more-than-one-renderer-open-ar_t)); its command lists hold no voices in the boot, the movie clips, the intro film and the first level, so what it is for is not known.
- **Timing:** the screens come at different times from run to run; drive it with `DM_CTL` (A / B lines) while watching `shot`s. The first run needs: A (language), A (seizure warning), B (accessibility options: No), then A through the title screen's notices to the new-game menu.
- **Sound and controller in the level (checked):** the audio renderer's mix (`DM_AUDREN_DUMP`) has music and effects from the menus on, at normal levels without clipping, left and right alike (not listened to); the left stick moves Leia, Plus opens the pause menu ("Paused – A New Hope – Boarding Party"). The movie's own `AudioOut` path and a real controller were not tested.
- The 363 files of mode 6 (`ZIPX`, scrambled; 73 MB in all) are not read by the shader split; it is not known whether one holds shaders.
